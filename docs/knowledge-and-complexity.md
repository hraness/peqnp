# Knowledge, clues, and computational complexity

Research note, 9 September 2026. [Album Shen](https://www.linkedin.com/in/albumshen) contributed the motivating taxonomy and discussion of clues that make subsequent solving more manageable. The motivation includes both clues revealed by solutions and side information such as insider knowledge about an opponent. The formal statements below are this project's analysis; conceptual collaboration does not imply endorsement of those statements. No resolution of P versus NP is claimed.

## Make the clue hypothesis precise

The useful hypothesis is that **reliable side information can eliminate choices until an exact deterministic procedure becomes tractable**. This includes inferred constraints, reusable domain facts, observations of hidden state, and information about an opponent's strategy. The research question is whether acquiring, representing, selecting, and applying enough such clues can have polynomial total worst-case cost for every input. “More manageable” in experiments is a valuable, weaker outcome. Additional knowledge is not established as necessary for every efficient algorithm.

For a Boolean formula F, let Models(F) be its satisfying assignments. An entailed clause c holds in every member of Models(F). A backbone literal is a literal true in every satisfying assignment of a satisfiable formula. Such information can be implicit:

\[
F=(x\lor y)\land(x\lor\neg y)\quad\Longrightarrow\quad x.
\]

Neither input clause is a unit, yet x is forced. Here a short resolution argument exposes the clue directly. Examining solutions can suggest the rule; a proof establishes its validity beyond the examples. Agreement among sampled solutions is insufficient: an unseen solution may violate the apparent clue. Require nonempty Models(F) when discussing backbones, since universal statements over an empty solution set hold vacuously.

There is a precise obstacle to making extraction free. Given any CNF F, introduce fresh x and define

\[
G=\bigwedge_{C\in F}(x\lor C).
\]

G is always satisfiable by setting x=true. Setting x=false leaves exactly F. Therefore **x is a backbone of G if and only if F is unsatisfiable**. This polynomial transformation proves that exact backbone membership on arbitrary satisfiable CNFs is coNP-hard. It even supplies an easy satisfying assignment; one known solution does not make all forced clues easy to recover. This is an elementary deduction here from the definitions and standard SAT completeness. [Cook's statement](https://www.claymath.org/wp-content/uploads/2022/06/pvsnp.pdf)

## Which kind of knowledge is available?

| Knowledge resource | Mathematical interpretation | Required accounting |
| --- | --- | --- |
| One fixed finite library of proved rules or finite-precision model weights | Can be included in one uniform program | Lookup, inference, and application costs; fixed knowledge is permitted by P |
| K(x) computed from the current input, or K_n generated from 1^n | Uniform preprocessing | Include generation, representation size, and subsequent computation |
| A polynomial-length K_n supplied separately for each input length n | Polynomial advice: the same advice serves every n-bit input | Exact polynomial-time use gives P/poly, without guaranteeing an efficient advice generator |
| Arbitrary information chosen for the particular x | Instance-specific assistance | An unverified answer bit already trivializes decision; a SAT witness only certifies a yes-instance |
| Access to an external set O through queries | An oracle model such as P^O | Specify the oracle and query costs; access to SAT does not prove SAT belongs to ordinary P |
| Feedback about a hidden state, as in a guessing game | Interactive information acquisition | Define observations, possible hidden states, rounds, and success guarantees |
| Insider information about an opponent's policy or private state | Side information in a specified game model | State reliability and acquisition; a policy prediction need not support a worst-case guarantee against every opponent |

Polynomial advice and uniform algorithms are different quantifier structures: “for every n, an appropriate K_n exists” does not supply one efficient construction for all n. The standard circuit/advice equivalence explains why polynomial-size learned artifacts, if supplied by length and exactly correct, naturally fit P/poly. [Arora and Barak, Chapter 6](https://theory.cs.princeton.edu/complexity/book.pdf)

For learning, state the data source, access protocol, training resources, model size, and error guarantee. Distributional accuracy does not imply exact correctness on every input. If labels or feedback require solving the hard problem, acquisition cannot disappear from a claimed uniform bound. [Valiant's original learning framework](https://courses.grainger.illinois.edu/ece544na/fa2014/valiant84.pdf)

## A simple theorem and the unresolved work

**Composition lemma.** Fix a finite library B and deterministic algorithms C and D. Suppose C(x,B) produces K in at most p(n) bit operations with |K|≤p(n), where n=|x|. Suppose D(x,K,B) always returns the correct decision in at most q(n+|K|) bit operations, for fixed nondecreasing polynomial bounds p and q. Then their composition decides the language in polynomial time.

**Proof.** Include B in the program. Compute K, then run D. Total time is at most p(n)+q(n+p(n)), a polynomial. The claim requires total correctness on yes- and no-instances, including all intermediate data costs.

Applied to general SAT, these hypotheses would establish P=NP. The lemma is elementary closure under composition; it supplies no missing compiler or decider. To make the investigation substantive, fix a clue language, sound extraction rules, a deterministic consumer, and an explicit bound. Seek proofs of adequacy and cost for increasingly broad families, retaining counterexamples when a claim fails.

Knowledge compilation studies a closely related tradeoff: compile a theory offline into a representation supporting cheap repeated queries. Its three distinct concerns are representation size, supported queries, and supported transformations. Fast online answers can coexist with expensive compilation. [Darwiche and Marquis](https://www.cs.cmu.edu/afs/cs.cmu.edu/project/jair/pub/volume17/darwiche02a.pdf) For m queries, report both total cost T_compile+ΣT_query and its amortized value; amortization does not prove polynomial one-instance SAT complexity.

Some proposed representations have known limitations: there are CNFs requiring exponentially larger equivalent DNNFs. Thus universal polynomial compilation into that specific language is not an open route to assume; use a stated restricted family or investigate another representation. [Bova et al.](https://www.ijcai.org/Proceedings/16/Papers/147.pdf)

## A clue-transfer experiment

The [first completed clue-transfer experiment](../experiments/clue-transfer.md) implements a small version of this design: exhaustively solve a tiny training corpus, extract entailed units, justify their reuse under renaming, freeze the library, and compare the same deterministic solver on larger cases with and without its preprocessing. All 122 cases were solved correctly, but matching overhead exceeded the residual search savings on every case. The [theory note](clue-transfer-theory.md) explains the soundness argument and why this narrow rule library misses some implicit structure even in 2-SAT.

Wider experiments should extract short entailed clauses or other reusable rule schemas and independently prove each schema sound. Count extraction, training, lookup, rule application, intermediate growth, and residual search separately. Preserve failures and distinguish finite observations from general proofs.

This tests three specific ideas: **acquisition** of implicit structure, **compression** into reusable rules, and **transfer** that reduces later work. It does not grant the tested solver access to the held-out solution sets. A later game experiment can compare strategies with and without specified opponent information, measuring benefit conditional on its accuracy. Clues may remove branches without removing exponential worst-case growth. Nondeterminism in NP is a mathematical computation model, not simply uncertainty about hidden facts or an opponent. Additional observations change the information available; their benefit must be distinguished from solving the original information-restricted task.

## Interfaces, free lunches, and the cost of reading a clue

Michael Levin's [Ingressing Minds](https://doi.org/10.3390/philosophies11050161) (Philosophies 11(5):161, 9 September 2026) proposes that bodies, machines, and algorithms are pointers, or interfaces, into a structured latent space of patterns, and that a good interface returns more than was put into it: a free lunch. His examples are mathematical. Two angles of a Euclidean triangle determine the third without further search. A voltage-gated ion channel gives evolution a transistor, and with it every logic gate and the universality of NAND, without any need to evolve the gates' truth tables separately. He proposes to quantify "the delta between effort put into creating specific embodiments and the resulting competencies", and states a refutation criterion: if no such input beyond conventional accounting is ever quantified, the framework should be dropped.

Ben Guo suggested that this bears on P versus NP. This project adopts the operational part of the proposal and gives it a precise computational reading. It takes no position on the article's metaphysics of non-physical or agential patterns, which the experiments here cannot test. The full text read for this section is the accepted [preprint v4](https://doi.org/10.31234/osf.io/5g2xj_v4) of June 2026, which carries the published title; the publisher's page blocks automated retrieval, so quotations were checked against the preprint.

**A pointer is a certificate, and P versus NP is about finding one.** Levin's central image is the pointer. A short function such as z³+7 "points" at a Halley fractal: following the pointer with the root-finding method reveals a rich pattern, and he insists this is not compression, because no algorithm takes the image and returns its seed. The same asymmetry defines NP. A certificate is a short pointer whose referent, the accepted instance, can be checked in polynomial time; the open question is whether a pointer can always be found as cheaply as it can be followed. Levin's free lunches are the cases where it can: given the referent, two known angles hand over the third, and a transistor hands over every gate. Read computationally, his framework asserts that following pointers is cheap and that the interface deciding which patterns come through must be investigated. P = NP is equivalent to the statement that every efficiently followable pointer is efficiently findable from its referent, by the standard self-reducibility of search to decision. Nothing in the article decides that; it locates the question exactly.

**Poincaré's examiner is the clue hypothesis.** The article opens its central section with Poincaré's account of invention: sterile combinations never present themselves, as if a prior examination had already eliminated them. That is Ben Guo's hypothesis in 1921 dress. A clue is a sound reason to discard candidates before search reaches them, and the composition lemma above says that if a polynomial-time examiner always leaves a polynomially small set of candidates for a polynomial-time consumer, the language is in P. What the examiner costs, and how many candidates survive it on every input, are the two quantities this project measures. Levin's use of Kauffman's "adjacent possible", the claim that past interactions with the space of patterns carry information about neighbouring patterns, is the same idea across instances rather than within one: it is what the clue-transfer experiment tested when it froze rules mined from solved formulas and applied them to unseen ones. The rules transferred soundly and did not pay for themselves, which is a measurement of how much the adjacent possible was worth for that library.

**The free lunch is entailment, and its price depends on the representation.** The third angle is entailed by the other two; a NAND truth table is entailed by the channel's transfer function. In SAT, a backbone literal or an entailed clause is likewise fully determined by the input formula. It is already there. But the construction G above shows that reading a determined clue can cost as much as deciding the original problem: whether x is a backbone of G is coNP-hard, even though G comes with a free satisfying assignment. The triangle and the gate are free lunches because their entailments have short known derivations in the representation at hand. So the phrase "more out than you put in" has a sharp translation: the information is fixed by the input, and the open quantity is the cost of the interface that exposes it. P versus NP asks whether, for every problem with polynomially checkable certificates, one uniform interface makes every such entailment cheap to read on every input. That universal claim is the problem itself and cannot be assumed.

**An interface is a representation with an access cost.** One 2-CNF has two interfaces here. As a clause list, the frozen two-clause library reads only the units it can match in one pass. As an implication graph, the same formula exposes every forced literal through a path from ¬l to l, and the strongly connected components of Aspvall, Plass, and Tarjan decide it in linear time. The F_k family in the [theory note](clue-transfer-theory.md#a-future-control-with-arbitrarily-long-binary-explanations) is a clue the first interface cannot see and the second reads directly. Levin's warning that the mapping from an interface to what comes through it "is almost always not linear or simple and must be investigated" is the reason this project measures rather than assumes. His sorting-array study with Zhang and Goldstein makes the same point in a minimal setting: deterministic algorithms show behaviors permitted by their steps but not prescribed by them, visible only under tests the algorithm was not written for. [Zhang, Goldstein, and Levin](https://arxiv.org/abs/2401.05375)

**"Free compute" has an accounted counterpart.** Levin's research agenda asks whether the latent space offers "policies, algorithms, or perhaps even virtual machines (free compute)", measured by the delta between effort put into an embodiment and the competency observed. Inside a closed cost model there is no unaccounted compute, but there is a quantity that plays the same role: the ratio between the cost of deciding a formula by enumerating its assignments and the cost of deciding it through an interface. On the implication-calibration corpus the truth-table reference spent 1,518,173 events and the graph decision 124,045; that twelvefold gap is the whole content of "2-SAT is in P", and it is a free lunch only in Levin's sense, because every event in the smaller number is charged. An algorithm is precisely a pointer whose following cost is less than enumeration. This project will report that enumeration-to-interface ratio alongside the interface delta from now on, so that a representation's accounted free lunch and its net worth against the baseline are both visible.

**Define the interface delta.** For an input F, a representation R, and a fixed deterministic consumer D, let

\[
\Delta(F,R)=T_{\text{baseline}}(F)-\bigl[T_{\text{build}}(F\to R)+T_{\text{read}}(R)+T_{\text{residual}}(D,F,\text{clues read from }R)\bigr],
\]

all in one declared cost model. Report any one-time acquisition of R's rules separately and amortize it only over an explicit batch. Δ is Levin's effort-versus-competency delta restricted to computation. The clue-transfer pilot measured Δ < 0 on every one of 122 cases: the library's clues were sound and reduced search, but reading them through pair enumeration cost about four times the baseline. By the article's own refutation criterion that interface fails. Two further experiments, each under a protocol frozen before its corpus existed, tested one interface for cheaper reading and one for wider coverage. The [sorted index](../experiments/indexed-transfer.md) reads the same clues for about one tenth of the generic matcher's cost and still has Δ < 0 on all 160 fresh cases. The [implication graph](../experiments/implication-calibration.md) reads every forced literal of a 2-CNF, including the F_k chains the library cannot start, and its linear-time decision with an explicit certificate still has Δ < 0 against the toy solver on 102 of 120 cases. The common cause is that the residual search on these small formulas was already cheap, so no T_build and T_read could be repaid. The [fragment-interface experiment](../experiments/fragment-interface.md) then added ternary clauses so that search is expensive and read only the binary fragment through the same graph. Δ was positive for the first time, on 22 of 162 cases, and 21 of those are cases where the fragment was unsatisfiable, so the read was the decision and T_residual was zero. Where the fragment's forced literals removed two thirds of the search nodes, extraction still cost more than it saved. A positive Δ from clues, as opposed to certificates, needs a cheaper read or an interface whose build cost is already paid.

**What the framework cannot supply.** Levin argues that no formal model fully captures a physical system, so a built machine may exhibit patterns its designers did not account for; his sorting arrays show delayed gratification and clustering that the code never prescribes. A P versus NP claim needs the opposite discipline: the cost model is closed, and every operation that builds or reads a clue is charged inside it. A contribution absent from the accounting cannot appear in a proof. Where the article looks for unaccounted competencies, this project looks for accounted ones and records the difference. The one sorting-array lesson that does carry over is methodological: a system's capabilities are found by testing it against goals it was not written for, and a missing clue is evidence about the observer's test, never proof that the clue is absent. The connection is a research heuristic and a measurement rule, not a proof step.

**How this changes the strategy.**

1. Representations are first-class candidates. The proposal's representation-and-decomposition family produces interfaces: indices, implication graphs, compiled forms, e-graphs. Each is evaluated by Δ on a fresh protocol-frozen corpus and promoted only with a proved polynomial bound on T_build and T_read.
2. Coverage and cost stay on separate axes. An interface that exposes more clues, as the implication graph does on F_k, is judged separately from one that exposes the same clues more cheaply, as the sorted index does. Both report phase costs, never a single clue count.
3. Prefer interfaces the consumer already pays for. Structures a solver builds anyway, such as watch lists, implication graphs, and learned clauses, have T_build already charged; their marginal T_read is the next quantity to measure, on formulas whose residual search is large enough to repay it.
4. A negative Δ is recorded, not tuned away. A representation family whose Δ stays negative across fresh corpora is retired in the ledger for that implementation, with its numbers.
5. Test interfaces where the residual is expensive. The first three corpora decide almost immediately under plain propagation, so no interface could show a positive delta on them. The fragment-interface experiment read the binary fragment of mixed 2/3-CNFs and found the delta positive only where the read decided the formula. The next protocol replaces the per-literal extraction with one linear pass over the component condensation, so that a fragment's forced literals cost O(n + m₂) to read.
6. The target is unchanged. A representation with Δ > 0 on every 3-SAT input, polynomial build and read costs, and a polynomial residual would be the algorithm the constructive target asks for. None is known.

## Turn the taxonomy into specifications

Human versus machine, guessing versus competition, and single versus multiple solutions are useful descriptive axes. They do not assign P or NP-completeness to parking, translation, eating, or a named game. Each research task needs an input encoding and size parameter, output or decision relation, available information, horizon, and correctness criterion. Distinguish deciding existence, finding one solution, counting, enumeration, and strategy selection. A formula can have an easy existence answer and exponentially many assignments to enumerate. Classify only the resulting formal problem, including promises and information access, after establishing the relevant bounds.
