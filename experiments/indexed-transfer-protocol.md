# Indexed transfer protocol v1

Specified before the held-out evaluation. This experiment compares the cost of applying the same frozen sound rule library, not new mathematical knowledge or an unrestricted SAT algorithm. Preserve `clue-transfer-v1` and its artifact unchanged.

## Frozen algorithms and rule compilation

Use the existing miner to acquire its four rule objects from the same 24 tiny candidate implications. Freeze those objects before constructing or labeling held-out cases. The three online arms are: no preprocessing; the unchanged v1 generic root matcher; and the indexed root matcher. All arms use precisely the existing deterministic unit-propagation/DPLL solver. Each online arm receives 1,000,000 total declared events, including its preprocessing. The indexed arm spends its remaining budget on the same residual solver.

The indexed compiler consumes the actual frozen rule objects in the generic matcher's two-source-variable grammar (variable IDs 1 and 2). It accepts the structural schema in which two binary premises share the conclusion literal, their other literals are complementary, and the shared and pivot variables are distinct. The four signed rule objects compile to one schema under signed injective renaming. The compiler checks every source rule and counts its reads, comparisons, and emitted schema storage. An empty library enables no inference; unsupported rules are rejected. Report mining and compilation once, separately from online matching and independent reference labeling. No truth-table or solver call occurs in the compiler, matcher, or candidate runtime.

For each eligible binary input clause `(a or b)` with distinct variables, the indexed matcher stores two entries `(a,b,clause_index)` and `(b,a,clause_index)`. An explicit in-place heapsort orders entries by shared signed literal, absolute pivot variable, and original clause index. A linear scan finds groups with both pivot signs. The earliest original index of each sign supplies the earliest witness pair for that group. Shared-literal blocks are contiguous in this index. Reduce each block to its lexicographically earliest pair `(min_index,max_index)` across pivot groups, emitting at most one witness for its unit. Apply the same explicit heapsort to the witnesses by those pairs before appending units to a copy of the original formula.

Every nonempty accepted library consists of signed variants of the same schema. Therefore a pair matches the generic matcher exactly when the corresponding index group has opposite signs. Generic enumeration visits clause pairs lexicographically; each matching pair yields only its shared literal. Selecting each unit's first witness pair and ordering by those pairs reproduces the generic arm's exact derived-unit order, including duplicate clauses and reordered literals. When both preprocessing phases complete, their processed formulas must be identical. When both entire arms complete, their residual solver event counts must also be identical; different preprocessing costs leave different residual budgets, so this latter assertion does not apply to an exhausted arm. Any disagreement invalidates the run; an arm exhausting its budget is not required to expose partial deductions.

## Fresh evaluation corpus

Use 160 cases, never the tuning corpus. Random cases are the Cartesian product of base seeds `1201, 5179, 65539, 104729`, declared variable counts `6,8,10,12`, clause densities `2,4,6`, and three families: pure binary (tag 1), pure ternary (tag 2), and mixed binary/ternary (tag 3). This gives 144 random cases. For each case, initialize a nonzero unsigned 64-bit RNG state as

`base_seed XOR (variables << 32) XOR (density << 40) XOR (family_tag << 48)`.

These fields occupy disjoint bits for the fixed parameter domain. The RNG applies the existing xorshift64 transition, in order: `x ^= x << 13; x ^= x >> 7; x ^= x << 17`, with 64-bit truncation after left shifts. Emit `variables * density` clauses. Pure families use their fixed width and consume no width draw. Mixed clauses use one draw, choosing width 2 for an even result and 3 for an odd result. Draw a variable as `(next() % variables)+1`; reject variables already occurring in the current clause before drawing a sign. For an accepted variable, another draw chooses positive for even and negative for odd. Preserve draw, literal, and clause order. Parameter-specific initial states avoid the deliberate shared density prefixes in v1; no claim of statistical independence follows from a pseudorandom generator.

The other 16 cases are explicitly engineered duplicate-pressure controls: variable count `6,8,10,12`, target sign positive/negative, and repetition count `1,8`. Set the shared literal to the signed highest variable. For each repetition in order, and each pivot from 1 through `variables-1` in order, append `(shared or pivot)` then `(shared or not pivot)`. Every declared variable occurs. These easy satisfiable formulas force the shared literal; repetition changes representation and matching work without changing their solution set. They are mechanism and overhead controls, not representative SAT instances. Generic matching may exhaust its budget on them.

Record every full input CNF, its declared and active variable counts, family and generation parameters. Before evaluation, reject any exact `(declared_variables, ordered_CNF)` overlap with the old 122-case corpus or another new case. This is exact input freshness, not a claim that cases are nonisomorphic or unrelated to known constructions. No generator changes or selection based on observed results are permitted. Independently enumerate every assignment for each case after freezing the library; report labeling work outside the algorithm comparison.

## Declared costs and storage

Retain v1's event categories and meaning. Each checked event consumes one unit: formula/header checks; clause reads/writes; literal or scalar reads/writes; assignments; pair/key comparisons; rule attempts; and search nodes. All counters and budget arithmetic are checked. Index construction charges reading each eligible input clause, creating both three-scalar entries, and every entry field written. Key comparisons charge the scalar fields inspected plus a comparison event. Heapsort charges each scalar read and write when swapping entries. Scanning charges group-key and sign reads, lookups, and retained witness state. Deduplication and witness ordering charge comparisons, scalar state, and copies. Appending units and copying formulas retain the common v1 charging. Compiler reads and schema storage are separately charged.

Supplementary index counters record entry count, key comparisons, group lookups, entry swaps, and peak explicitly stored scalar cells in the entry array, witness array, and derived-unit list (three cells per entry/witness and one per unit). This is auxiliary structure size, excluding the common output formula, frozen library, constant-size scalar locals, and allocator capacity overhead; it is not whole-process peak memory. They describe operations already charged in the event total, not additional work to add again. Vector capacity/allocator internals, loop-control arithmetic, diagnostics, input generation and JSON serialization remain outside this operational metric, as in v1. Disclose that scope: event counts are neither elapsed time nor a proved bit-cost bound. No opaque hash-map or sorting implementation is counted as one free operation.

For `m` eligible binary clauses and `n` declared variables, the oriented index has `2m` entries, heapsort takes `O(m log(m+1))` scalar comparisons/moves and `O(m)` stored scalar cells, and the sorted-group scan is linear. Reducing contiguous shared-literal blocks deduplicates witnesses in linear work. Each inferred unit requires at least two oriented entries, so there are at most `m` witnesses; sorting them costs `O(m log(m+1))`. The complete preprocessor therefore uses `O(L + m log(m+1))` scalar events and `O(m)` auxiliary scalar cells, where `L` counts input literals and clause headers. This bound does not rely on fixing the variable count. It concerns this limited preprocessor, not the complete SAT solver. Scalar values require `O(log(L+n+1))` bits under an unbounded abstract implementation; this Rust experiment instead uses bounded machine integers and rejects unsupported input/resource limits. Generic pair enumeration has quadratic pair count and repeated rule work. Both algorithms may still be dominated by the shared exponential DPLL search.

## Scoring and acceptance

Every completed answer must agree with the independent reference. Timeout means unknown, never UNSAT. Report each arm's preprocessing, residual and total online work, derived units, search nodes, completions and unknowns. Report all three pairwise better/tied/worse comparisons only when both arms complete correctly; report completion differences separately. Family totals and engineered controls stay separate. Do not treat an unfinished arm's smaller work count as a speedup.

Report one-time mining and compilation, online totals, and the corresponding setup-plus-online totals. Only compute amortization where completed comparable cases provide positive online savings. Do not infer broad performance or complexity from this small corpus, nor tune after seeing it. Focused acceptance checks cover exact unit/order equivalence on exhaustive small development formulas, independent SAT labels, signs/permutations/duplicates/tautologies, empty and malformed libraries or formulas, charged index storage, and exact budget exhaustion.
