## Question and distinct outputs

The five completed experiments read forced literals from a binary fragment and found the interface delta positive only where the read decided the formula. They never measured what the forced literals are a part of: the structure of the solution set itself. The statistical-physics picture of random 3-SAT predicts that as clause density α = m/n rises the solution set passes from one connected region to exponentially many clusters (clustering, α_d ≈ 3.86 for k = 3, where condensation coincides), then to clusters with extensively many frozen variables (α_f ≈ 4.254 for k = 3, the exhaustive measurement 4.254 ± 0.009 of Ardelius and Zdeborová, which is consistent with the cavity-method freezing analysis of Semerjian; Krzakala et al. 2007 tabulate k = 4, 5, 6 only and give α_d(3) ≈ 3.86 in prose), then to unsatisfiability (α_s ≈ 4.267, Mertens, Mézard, and Zecchina), all at n → ∞ and by the non-rigorous cavity method. This experiment measures the finite-size counterparts with this repository's tooling and asks three things: how model count, backbone, clusters, frozen variables, and inter-cluster distances vary with density at 8 to 24 variables, **in excess of what a uniformly random point set of the same size shows**; whether a local-move solver's cost tracks frozen variables; and how biased solver-sampled solutions are against the exact distribution where both are available.

Every case runs two decision arms, each under one budget of 1,000,000 declared events, and one geometry procedure outside both:

1. **Baseline:** the existing deterministic unit-propagation/DPLL solver on the original formula, with its 12-variable validation limit lifted to the case's n. Rust has no default parameters, so the lift is by sibling functions rather than a defaulted argument: `transfer::validate_within(input, variables, max_variables, meter)` receives the body of `transfer::validate`, which becomes the one-line wrapper passing 12; `transfer::decide_within` and `transfer::solve_within` carry the same extra argument down to it, with `decide` and `solve` as wrappers passing 12 (the call of `decide` inside `solve`, at `src/transfer.rs` line 546 at the freeze commit's parent, becomes the call of `decide_within` inside `solve_within`). The driver calls `solve_within(input, n, None, budget, n)`. Every existing call site of the three wrappers is unchanged, sixteen at the freeze commit's parent: `validate` at `src/transfer.rs` lines 170, 340, and 507, `src/indexed.rs` line 294, and `src/implication.rs` line 117; `decide` at `src/transfer.rs` line 546, `src/fragment.rs` line 166, and `src/extraction.rs` line 475; `solve` at `src/transfer.rs` lines 831 and 832, `src/indexed.rs` lines 431, 740, and 741, `src/implication.rs` line 1468, `src/fragment.rs` line 806, and `src/extraction.rs` line 1165. Because every wrapper still passes 12, the earlier experiments' bytes are unchanged, which the gate's replay loop verifies.
2. **WalkSAT:** the deterministic local-move solver below (WalkSAT/SKC with noise 1/2), a SAT-only witness finder that returns unknown on budget exhaustion and never UNSAT.
3. **Geometry:** for n ≤ 12, exhaustive enumeration, clustering, freezing, distances, whitening, and a seeded null point set, charged on one geometry meter with limit `u64::MAX` and reported outside the arms; for n ≥ 16, the declared oracle with the sampling and backbone procedures below, reported as call counts and verified-proof lemma counts per purpose, plus the charged Rust-side model checks, proof checks, and whitening events. No wall-clock seconds and no solver-reported conflict counts enter the artifact.

No label, model set, backbone, sample, null set, or oracle answer reaches arm 1 or arm 2: arm functions keep the signature `(input, n, budget)`, they import neither `oracle` nor the geometry statistics, and the driver performs every reference lookup and every geometry procedure for a case only after both arms have returned for it. The geometry procedure is a measurement, not a competitor; the only arm comparison is WalkSAT against the baseline on reference-SAT cases both complete, as better, tied, and worse counts on total events with completion differences. Comparisons and every curve count only cases whose label is known and, where an arm enters, on which every compared arm completed; every unknown case stays in the artifact, is listed in every table of its (n, α) cell with its arm outcomes, is counted in the unknown column, and is never re-drawn.

Reference model string, as the oracle design requires: `"truth-table<=12;definition;oracle:cadical-3.0.1+model-check+lrat-check"`. Truth-table cases: every case with n ≤ 12 (the small regime, including the calibration subset). Oracle cases: every case with n ≥ 16 (the large regime). Definition cases: none by construction, since every formula has at least 16 clauses and no empty clause, and composed calls append unit clauses only; the driver asserts `definition_cases = 0` as an implementation check.

## Event categories, numbers, and randomness

**Event categories.** Every charge names one of the nine existing checked categories of `transfer::Event`: formula check, clause read, clause write, literal read, literal write, assignment, pair check, rule attempt, search node. "Container read/write" charges the clause counters and "scalar read/write" charges the literal counters, as in the extraction-cost protocol; "popcount" is one scalar read. Comparisons, arithmetic, and loop control are not charged, as in every earlier protocol. No procedure charges outside these nine; the model checker and the LRAT checker charge exactly what `oracle::check_model` and `oracle::check_lrat` (through `lrat::propagate`) tick (the model checker: one formula check, one clause write, one literal write per variable, one clause read per clause, one literal read per literal examined; the LRAT checker: formula checks, clause reads, literal reads, literal writes), on a checker meter outside all arms.

**Numbers.** Every integer quantity is a JSON integer. Every non-integer quantity is a `RatioPair` object `{"numerator":a,"denominator":b,"thousandths":"q.rrr"}` with `thousandths = (a·1000 + b div 2) div b` in checked integer arithmetic (half rounded up, exactly `fragment::ratio` and `oracle::ratio_pair`), or `null` when b = 0 or the arithmetic overflows. A signed non-integer quantity is a `SignedRatioPair` object `{"negative":false|true,"numerator":|a|,"denominator":b,"thousandths":"q.rrr"}` whose magnitude fields are the `RatioPair` of |a| and b computed as above (so a rounding tie rounds up in magnitude, away from zero, for either sign: a = −1, b = 2000 gives `thousandths` `-0.001`) and whose `thousandths` string carries a leading `-` when `negative` is true and |a| > 0; zero is never negative. Signed quantities are the per-case differences Δ_B and Δ_c, every mean paired difference, every difference of means, and every crossover statistic defined as a signed mean; each is named as signed where it is defined. No floating point reaches any artifact. Per-case rows store integers only (sums, counts, sizes, lists); every fraction is formed at the summary level from those integers, so the row is the authority and any aggregate can be recomputed from it.

- **Per-case fraction** of a statistic X with integer numerator a_i and denominator b_i (for example the size-weighted frozen fraction Σ_K |K|·frozen(K) over |S|·n): its thousandths integer is t_i = (a_i·1000 + b_i div 2) div b_i; for a signed per-case quantity, t_i is the thousandths of |a_i| with the sign restored, exactly the `SignedRatioPair` rule.
- **Cell mean** of X over k cases: the `RatioPair` (Σ t_i, 1000·k), called the thousandths mean. It is the exact mean of the rounded per-case values; the rounding is at most 1/2000 per case and is declared here so that two implementations produce identical bytes without a common denominator that could overflow. Means with a fixed denominator across the cell (|B|/n, success rates, indicator fractions, model-count bit lengths, and the cell mean of Δ_B, whose denominator is n) are exact ratios of integer sums, (Σ a_i, k·b). In every cell mean, k is the number of cases of the cell in which X is **defined**: a case in which the per-case statistic is undefined (the restricted frozen fraction with no cluster of size at least two, an inter-cluster distance mean with one cluster, a pairwise point distance with fewer than two points, a sample distance with fewer than two distinct samples, a backbone fraction with an unknown backbone, the null differences Δ_B and Δ_c on a case with |S| = 1 as claim 1 states, and every statistic of a case whose label is unknown) is excluded, k is reported beside every cell mean, and the mean is `null` when k = 0. The 10-SAT rule of the curves section counts the cell's reference-SAT cases, not k.
- **Median** of per-case rationals: the lower median, sorting by cross-multiplication in checked `u128`, ties by numerator, element ⌈k/2⌉ (1-indexed). Medians of integers (model counts, flips, events) are lower medians of integers. For arm event counts and search nodes the median is right-censored: unknown outcomes sort as +∞, so the median is defined when at least ⌈k/2⌉ of the k labelled cases completed and is `null` otherwise.
- **Minimum and maximum** are exact.
- **Paired differences.** One rule covers every mean paired difference of this protocol (claims 1 and 2): over all k_def defined pairs of the comparison, zero differences included, the mean paired difference is the thousandths mean (Σ_i (t_i − t′_i), 1000·k_def) of the per-case signed thousandths t_i and t′_i of the two members of each pair, a `SignedRatioPair` compared to its threshold by cross-multiplication. This rule applies to Δ_B (denominator n, where the exact ratio of integer sums would also be available) and to Δ_c (denominator |S|, varying across cases) alike, so that no case distinction exists; the per-case rounding is at most 1/2000 against thresholds of 1/4. The sign test's k is the number of those k_def pairs whose difference is nonzero (a difference is zero exactly when the two per-case rationals are equal by cross-multiplication), and every claim verdict on paired data reports both k_def and k. Crossover statistics 1 and 2 are not paired differences: they are the cell means of Δ_B (the exact ratio (Σ_i (|B(S_i)| − |B(N_i)|), k·n) under the fixed-denominator rule) and of Δ_c (the thousandths mean) over the cell's defined cases.
- **Bit length** of an integer x ≥ 1 is ⌊log₂ x⌋ + 1, computed by shifting; no logarithm is taken anywhere.

**Sign test.** The only inferential device on paired data is the one-sided sign test: for k pairs with nonzero difference and s differences in the claimed direction, P = Σ_{i=s}^{k} C(k, i) / 2ᵏ, computed exactly in checked 128-bit arithmetic (k ≤ 20 here) and reported as the rational (numerator, 2ᵏ) plus its thousandths string. The null is that the two compared densities draw the paired quantity from one distribution, under which each sign is a fair coin. A claim is **held** when k ≥ 7, 100·numerator < 2ᵏ (P < 1/100), and its effect criterion holds; **falsified** when k ≥ 7 and either fails; **not testable** when k < 7, which is reported and never counted as held. The minimum k = 7 is the smallest number of pairs at which P < 1/100 is attainable at all (1/2⁷ = 1/128 < 1/100 < 1/64 = 1/2⁶), so a held verdict at k = 7 requires seven of seven signs; a minimum of 10 would leave claim 4 testable in the large regime only when all 10 replicate pairs are reference-SAT and solved at both densities, which at P(SAT) near 1/2 at α = 4.25 has probability about 1/1000 per n. Pairs are formed by replicate index r between the two named densities; the pairing is by index only, since the two members are independent formulas (their effective seeds differ in the m field) sharing no structure, so the test is a valid two-sample test that carries no paired power. A pair is dropped when either case is unknown or, for statistics over SAT cases, when either case is not reference-SAT, or when either side's statistic is undefined. No multiplicity correction is applied across the per-n sign tests of claims 1 to 4 (three tests each for claims 1 to 3, six for claim 4): each n is its own registered claim with its own P at the 1/100 threshold, and the number of held verdicts among them is reported as a count, never combined into one P.

**Bootstrap.** Where an interval is named, it is a seeded percentile bootstrap with B = 1,000 resamples: for k per-case values, each resample draws k indices `next() mod k` from the named stream, computes the thousandths mean (or the exact-ratio mean, or the crossover, as the statistic's definition says), and the B results are sorted ascending with the rules above; the interval is elements 26 and 975 (1-indexed). Intervals are descriptive and are used in a claim only where the claim says so. Every bootstrapped statistic has one stream of its own, and the complete enumeration is the following; no other statistic carries an interval, and no two intervals share a stream.

- **Per-cell intervals** (stream `mix(0x6765_6f6d_6574_7279 XOR (5 << 60) XOR (c << 32) XOR i)`), for cell index c from 0 to 53 in cell enumeration order (the 36 small-regime cells, n outermost then q ascending, then the 18 large-regime cells in the same order) and statistic index i: i = 0, the cell mean of |B|/n over SAT cases with a known backbone (the exact ratio (Σ|B|, k·n)); i = 1, the cell mean of the per-case mean pairwise Hamming distance over n among distinct known samples (thousandths mean over cases with at least two distinct samples). Both are computed in every cell where k ≥ 1 and are `null` otherwise; the values in the pool are the cell's defined cases in enumeration order. Claim 7 uses i = 0 and i = 1 in the large-regime cells.
- **Pooled intervals** (stream `mix(0x6765_6f6d_6574_7279 XOR (6 << 60) XOR i)`), over cases pooled across cells in enumeration order, statistic index i: i = 0, the mean of Q_core(W) and i = 1, the mean of Q_cluster(W) of claim 5 (over reference-SAT small-regime cases with |S| ≥ 2 and a WalkSAT model); i = 2, the mean over calibration cases of the per-case mean Q_core over known samples, and i = 3, the same for Q_cluster (claim 6a); i = 4 and i = 5, the null counterparts of i = 2 and i = 3 (claim 6c). The total-variation distances of claim 6 carry no interval.
- **Crossover intervals** (stream `mix(0x6765_6f6d_6574_7279 XOR (7 << 60) XOR (n << 32) XOR i)`), one stream per variable count n (the literal value 8, 10, 12, 16, 20, or 24) and crossover index i from the crossover list of the curves section (0: P(SAT) below 1/2; 1: mean Δ_B above 1/10; 2: mean Δ_B above 1/4; 3: unconditional P_unfrozen below 1/2; 4: P_unfrozen|SAT below 1/2; 5: multi-cluster fraction above 1/2; 6: WalkSAT success below 9/10; 7: WalkSAT success below 1/2). Each resample draws R indices `next() mod R`, where R is the replicate count of that n (20 in the small regime, 10 in the large), and the one drawn index multiset is applied to every cell of that n: each cell's statistic is recomputed on the resampled rows, counted with multiplicity, under the same definedness, unknown-exclusion, and 10-SAT rules as the point estimate, and the crossover is then the first grid α where the condition holds, with "not reached" sorting as +∞.

The bootstrap streams do not depend on any `effective_seed`; the constant is the ASCII of `geometry`.

**Randomness.** All streams are xorshift64: `x ^= x << 13; x ^= x >> 7; x ^= x << 17` on a 64-bit unsigned state with truncating shifts. The corpus generator's stream starts at the case's `effective_seed` (below). Every other per-case stream starts at `mix(effective_seed XOR tag)` where `mix` is the splitmix64 finalizer, `x ^= x >> 30; x = x · 0xbf58476d1ce4e5b9; x ^= x >> 27; x = x · 0x94d049bb133111eb; x ^= x >> 31` with the two multiplications explicitly wrapping (`wrapping_mul`, the only wrapping arithmetic in the experiment, confined to this function), and a result of 0 replaced by 1. Tags: WalkSAT `1 << 60`; sampler stream j `(2 << 60) XOR (j << 48)`; null point set `3 << 60`; calibration null draws `4 << 60`. The bootstrap streams (tags `5 << 60`, `6 << 60`, and `7 << 60`) are the three families enumerated above, started from the fixed constant rather than a case seed. The mixer is nonlinear over GF(2), so no arm's or procedure's random choices are an affine function of the generator draws that built the instance; an affine start such as `effective_seed XOR (1 << 60)` would make every derived stream exactly such a function, which is why the mixer is interposed. `(next() mod i) + 1` is written with its parentheses throughout and matches the generator idiom `rng.next() % n + 1`.

## Definitions and exact procedures

An assignment is an n-bit integer whose bit v−1 is the value of variable v, 1 meaning true, as in the truth-table enumerator. The **model set** S is the set of satisfying assignments, held as a sorted ascending list. The **backbone** B is the set of literals true in every member of S, defined only when S is nonempty; for S it is taken from the reference (truth table or oracle procedure), never recomputed on the geometry meter.

**Null point set (small regime, SAT cases).** N is a uniformly random subset of {0,1}ⁿ of size |S| drawn from the null stream: a membership array of 2ⁿ cells starts false (one container write, 2ⁿ scalar writes); repeat `a = next() mod 2ⁿ`, charging one scalar read of `member[a]`; if already a member, draw again; else set it, charging one scalar write; stop after |S| acceptances (expected draws are at most |S|·2ⁿ/(2ⁿ − |S| + 1), and the loop terminates because |S| ≤ 2ⁿ). The sorted list is then read off the membership array in ascending index order, charging one scalar read per cell and one scalar write per member. N runs through the identical clustering, freezing, and distance code below. Its "backbone" B(N), the set of literals common to all its members, is computed by the frozen-variable procedure below applied to N as one cluster (the whole list, with the same accumulators, per-member and per-variable charges, and finalization), on the geometry meter; |B(N)| is the frozen count of that run. N is not a set of models; whitening is not defined on it. Every real-versus-null statement is about the real value minus the null value on the same formula.

**Clusters.** The primary cluster graph has vertex set S (or N) and an edge between two points at Hamming distance exactly 1; clusters are its connected components. The secondary graph joins points at distance at most 2. Union-find is deterministic and fully charged:

- Initialization: `parent[i] = i` for i in 0..|S|, one container write and |S| scalar writes.
- Lookup of a value x in the sorted list: `lo = 0, hi = len`; while `lo < hi`: `mid = lo + (hi − lo) div 2`, charge one scalar read of `list[mid]`; if `list[mid] < x` then `lo = mid + 1` else `hi = mid` (no early exit on equality). Then, if `lo < len`, charge one scalar read of `list[lo]`; found iff it equals x.
- `find(x)` with path halving: `while parent[x] != x { parent[x] = parent[parent[x]]; x = parent[x] }`; per iteration one scalar read of `parent[x]` (the test), one scalar read of `parent[parent[x]]`, and one scalar write; the final failing test charges one scalar read. `find(i)` runs before `find(j)`.
- `union(i, j)`: `a = find(i)`, `b = find(j)`; if `a == b` nothing more is charged; else `parent[max(a, b)] = min(a, b)`, one scalar write.
- Primary enumeration: for i in ascending order with `model = list[i]`, for v from 1 to n: `neighbor = model XOR (1 << (v−1))`, charging one scalar read (the model) and one scalar write (the neighbor cell); skip when `neighbor < model` (uncharged comparison); look up `neighbor`; if found at j, `union(i, j)`.
- Secondary enumeration: a **fresh** union-find, re-initialized and re-charged, receives the primary enumeration again (charged again) and then, for each i and each unordered pair u < v (u outer, v inner), `neighbor = model XOR (1 << (u−1)) XOR (1 << (v−1))`, charged, skipped when `neighbor < model`, looked up, and united identically.
- Cluster identity is the root; clusters are numbered by their smallest member ascending. Record the number of clusters, their sizes in cluster order, the largest size, and the secondary cluster count.

**Frozen variables.** Variable v is frozen in cluster K when every member of K gives it the same value. Compute by one pass over K's members in ascending order with two accumulators per variable (`all_true`, `all_false`, both starting true, charged one container write and 2n scalar writes): per member charge one scalar read of the point; per variable charge one scalar read for the bit test and one scalar write for the accumulator update. Finalization replicates the reference's backbone finalization: one container write for the frozen-literal list, two scalar reads per variable, one scalar write per frozen literal. The row stores per cluster of S and per cluster of N the frozen **count**, in cluster order beside the size list; the frozen-literal lists of S's clusters are computed in full, used for the containment checks below, and pinned by the row's geometry digest (artifact layout), not stored as lists, because at low density a list per cluster would dominate the artifact (sizing below); N's members follow from `effective_seed` and |S|, so N stores counts and |B(N)| only. Per formula the row stores the integers Σ_K |K|·frozen(K), Σ_K frozen(K), frozen(largest cluster) (the lowest-numbered largest cluster on ties), |B|, the number of singleton clusters, and Σ_{|K|≥2} |K|·frozen(K) with Σ_{|K|≥2} |K|; the summary forms the size-weighted frozen fraction (over |S|·n), the unweighted frozen fraction (over clusters·n), the largest-cluster frozen fraction (over n), |B|/n, the singleton-cluster fraction (over clusters), and the frozen fraction restricted to clusters of size at least two (over Σ_{|K|≥2}|K|·n, `null` when no such cluster exists). A singleton cluster has frozen fraction 1 by definition, which is why the restricted fraction and the singleton count are reported. Since every cluster is a subset of S, B is contained in each cluster's frozen literals; the run asserts this as an implementation check.

**Distances.** For each unordered pair of clusters (i < j in cluster-number order), the minimum Hamming distance between a member of i and a member of j, by scanning all member pairs (members ascending, i's member outer) **without early exit**, charging one pair check per pair and one scalar read per popcount; per-cluster-pair minima are stored as integers. The row stores the minimum over cluster pairs, the sum of minima, and the number of cluster pairs (0 when there is one cluster; the summary means are `null` then). By construction the minimum is at least 2 for distance-1 clusters and at least 3 for distance-2 clusters; a floor at those values is not a finding. Separately, the mean pairwise Hamming distance over all unordered point pairs is stored as the sum of distances and the number of pairs, charged the same way in a second scan (the two scans are charged separately and neither exits early); it is `null` when |S| < 2. Each scan is O(4ⁿ·n) events per formula and is outside the arms.

**Whitening (Parisi).** Given F and a model σ, an array `white` of n cells starts false, charged one container write and n scalar writes. Occurrence lists per variable are built **once per formula** on the geometry meter, charging one clause read per clause, one literal read per literal, one container write per list, and one scalar write per entry, and are reused for every model of that formula. A pass visits v from 1 to n: charge one scalar read of `white[v]`; skip v if already white. Otherwise, for each clause C containing v, in occurrence-list order, charge one clause read and examine C's literals in clause order: charge one literal read per literal examined; a literal on v itself is passed over (v is not white while being tested, matching Parisi's rule that the witness is a variable of C **other than v**); for a literal on another variable w, charge one scalar read of `white[w]` and, if w is white, C has its witness; else charge one scalar read of σ's bit for w and, if the literal is true under σ, C has its witness; examination of C stops at the first witness. **Examination of v's clauses stops at the first clause without a witness**: that clause is read to its end (every literal examined and charged as above, none a witness), v's remaining clauses in occurrence-list order are not read and charge nothing in this pass, and v stays non-white until the next pass. If every clause containing v has a witness, v becomes white immediately, charging one scalar write, and is visible as white to later variables **in the same pass** (Gauss–Seidel order); the resulting fixpoint is the least fixpoint of a monotone operator and does not depend on the order or on the stop rule, only the charges do. Passes repeat until one whitens nothing; at most n+1 passes, so O(n·L) events for total literal count L. The **core** of σ is the set of non-white variables; σ is **unfrozen** when its core is empty.

Containment, **proved generally** by the elementary argument recorded here: for a model σ in cluster K of the distance-1 graph, every variable not frozen in K is white in σ's whitening, so core(σ) ⊆ frozen(K). Proof. Let u be not frozen in K. Some τ ∈ K differs from σ on u, and since K is connected there is a path σ = σ₀, σ₁, …, σ_t = τ in K with consecutive models at Hamming distance 1; u flips at some step of this path. Fix the path and order the variables that flip at least once along it by the index of their first flip. Induction along that order shows that each such variable is white in σ's whitening. Let u first flip at step i, from σ_{i−1} to σ_i, and let C be any clause containing u. Both σ_{i−1} and σ_i satisfy C, they differ only in u, and u's literal in C is true in exactly one of them; in the **other** endpoint C is satisfied by a literal on some variable w ≠ u, and w has the same value in σ_{i−1} and σ_i. If w never flipped before step i, its value at that endpoint is its value in σ, so that literal is true in σ; otherwise w first flipped earlier and is white by the induction hypothesis. Thus every clause containing u has a witness of the kind the whitening rule accepts once all earlier-flipping variables are white; the whitening fixpoint is the least fixpoint of a monotone operator, so it contains each flipping variable in turn, and in particular u. Hence core(σ) ⊆ frozen(K). ∎ (An earlier form of the argument, "every clause containing u has another true literal in τ", was wrong for clauses in which u's literal is the unique true literal in τ; the corrected argument uses whichever endpoint falsifies u's literal.) The converse fails: in (x ∨ y) ∧ (x ∨ ¬y) with σ = (1,1), x is a backbone literal yet white after two passes (y first, then x). The containment is a theorem, so it is an implementation check (Acceptance and reporting), not a claim: the run asserts it on every model of the small regime, and the fraction of models on which the inclusion is strict is a descriptive statistic of the curves section; at n ≥ 16 no cluster is known, so sample core sizes there are descriptive and nothing is asserted about them.

**Quantile of a model against S.** For a model W of a small-regime formula and a per-model integer statistic X, the mid-rank quantile of W in the direction "smaller is better" is Q⁻(W) = (2·#{U ∈ S : X(U) > X(W)} + #{U ∈ S : X(U) = X(W)}) / (2·|S|), and in the direction "larger is better" Q⁺(W) = (2·#{U : X(U) < X(W)} + #{U : X(U) = X(W)}) / (2·|S|). Under W uniform on S the expectation of either quantile is exactly 1/2 for every formula, whatever the distribution of X (ties included), which is the null used for claims 5 and 6. Q_core(W) = Q⁻ with X = core size; Q_cluster(W) = Q⁺ with X = the size of W's distance-1 cluster. Each is stored as the integer numerator over 2·|S|. When X is constant over S (every model has the same core size, or S is one distance-1 cluster) both quantiles equal 1/2 for every W by construction; such a case is **degenerate** for that quantile, is counted and reported as such wherever the quantiles are pooled, and carries no information about W. The distribution of Q about 1/2 is not symmetric in general, so no sign test is applied to Q; means and bootstrap intervals are.

**WalkSAT/SKC, noise 1/2.** The stream starts at `mix(effective_seed XOR (1 << 60))`. The procedure, with every tick:

```
init:
  assignment: one container write; for v = 1..n: bit v = low bit of next(); one scalar write each
  occurrence lists occ[l] for the 2n literals: one container write per list;
    for each clause c in order: one clause read; for each literal l of c: one literal read, one scalar write (append c to occ[l])
  true counts: for each clause c: one clause read; for each literal: one literal read and one scalar read of its assignment bit;
    one scalar write of count[c]
  unsatisfied list U with position array pos: for each c with count[c] = 0: one container write (append), one scalar write (pos[c])
  flips = 0
step:
  if U is empty: return SAT with the assignment (no search node is charged for this check;
    a formula satisfied by the initial assignment reports 0 search nodes and 0 flips)
  charge one search node
  c = U[next() mod |U|]: one scalar read (the list entry), one container read (the clause)
  for each literal l of c in clause order: one literal read;
    t = the literal of var(l) true under the assignment: one scalar read of the bit;
    read occ[t]: one container read; for each entry d: one scalar read of count[d]; break(l) = #{d : count[d] = 1}
  if some break(l) = 0: flip the first such l in clause order (no draws)
  else: b = low bit of next(); if b = 1: flip literal number next() mod width(c) (0-indexed in clause order);
        if b = 0: flip the literal of minimum break, first in clause order on ties
  flip x = var(l): one scalar write (the bit); flips += 1 and the flip index of this step is recorded;
    for each d in occ[literal of x true before the flip]: one scalar read and one scalar write of count[d] (decrement);
      if count[d] became 0: append d to U: one container write, one scalar write (pos[d])
    for each d in occ[literal of x true after the flip]: one scalar read and one scalar write of count[d] (increment);
      if count[d] became 1: swap-remove d from U: two scalar reads (pos[d], last entry), two scalar writes
        (moved entry, its pos), one container write (pop)
  repeat
```

Three costs are **explicitly uncharged** so that two implementations agree: the allocation of the `pos` array at initialization (no container write and no scalar writes; a `pos` entry is charged only when written as a clause enters or moves within U), the test `count[c] = 0` in the loop that builds U (it reads a value the same procedure has just written and is treated as loop control), and the read of x's bit at "flip x" to determine the literal true before the flip (that bit was read, and charged, as t in the break computation of the same step). Everything else in the listing is charged as written.

The draw order is fixed: the clause index draw, then break counts with no draw, then the noise bit only when no break-0 literal exists, then the literal index draw only when the bit is 1. A SAT answer is verified by `oracle::check_model(input, n, model)`, which runs on its own fresh meter and returns its work in the `ModelCheck`; the driver adds that work to the checker totals outside the arm. The arm stops on SAT or when the meter refuses an event, returning unknown with its flip count. No restarts, no flip cap beyond the budget, no tuning after results. Because the run is deterministic and has no restarts, the recorded flip index at which SAT was returned yields success-within-f-flips curves after the fact without re-running, subject to the censoring rule of claim 4. Each step is O(occurrences) events; per-flip cost rises with α, so an event-budget success rate confounds landscape hardness with clause count, and flips are the primary WalkSAT statistic. This is the break-count, freebie-then-noise variant named SKC in McAllester, Selman, and Kautz (1997) and described in Selman, Kautz, and Cohen (1996), where the break-0 move precedes the noise draw; it is a single-agent local search, and the arm tests a local-move solver, not a collective model.

## Oracle procedures (n ≥ 16, and the calibration subset)

Every oracle call is an entry of the oracle-answer file keyed by the SHA-256 of its DIMACS text (`oracle::write_dimacs`: `p cnf n m`, F's clauses in order, then any appended unit clauses, duplicates kept, no dedup); calls with identical text share one entry. The conflict limit is `Limits { conflicts: 10000 }` (`-c 10000`), the only oracle limit; the per-entry proof-text cap is 2,097,152 bytes and the answer-file cap 16,777,216 bytes, both the design's constants. A SAT answer counts only after `check_model` verifies the model against the call's full DIMACS text (F and the appended units); an UNSAT answer only after `check_lrat` verifies the proof against that text. A conflict-limit answer or a proof over the cap is **unknown**; every other anomaly (parse failure, invalid model, invalid proof, digest, identity or limit mismatch, missing, duplicate or unused entry) is an error that stops the run, exactly as `oracle::read_answers` (parse failure, duplicate), `oracle::verify` (digest, identity, limit, model, proof), the digest lookup (missing), and `oracle::check_used` (unused) implement. Per case the calls run in this fixed order, each call's formula derived from the corpus and earlier entries only, and the artifact links each call to its entry by digest (through the row's `calls_sha256`, artifact layout):

1. **Decision:** one call on F. Label sat, unsat, or unknown. In the large regime this is the case's reference label; an unknown labels the case unknown and nothing further is called. On the calibration subset it is a composed call compared with the truth table and never the reference.
2. **Assumption-halving sampler**, after a sat decision. Sample 0 is the verified decision model. For j from 1 to K = 3, the stream starts at `mix(effective_seed XOR (2 << 60) XOR (j << 48))`. Draw a permutation π of 1..n by Fisher–Yates over the array `[1, …, n]`, swapping position i with position `(next() mod i) + 1` for i from n down to 2 (positions 1-indexed); then n further draws give value bits, the bit for variable π(i) taken from the low bit of draw i. Set r = n div 2. Loop: append the first r variables of π as unit clauses with their drawn values (bit 1 gives the positive literal, bit 0 the negative literal, the assignment convention of the definitions section), after F's clauses, in π order; call the oracle; on SAT, the verified model is sample j with depth r; on UNSAT with a verified proof, set r = r div 2 and repeat; when r reaches 0 no call is made, sample j is the decision model with depth 0 and is marked **collapsed**. On unknown, sample j is unknown and the sampler continues with j+1. Calls per sample are at most ⌊log₂(n div 2)⌋ + 1: 3 at n = 12 (r = 6, 3, 1), 4 at n = 16 (8, 4, 2, 1), 20 (10, 5, 2, 1), and 24 (12, 6, 3, 1). The known samples are sample 0 and the known samples 1..3, at most 4; the **distinct** samples are the distinct assignments among them (sample 0 and every collapsed sample coincide and count once). Solutions found this way are biased toward what the solver's deterministic search reaches from a random partial assignment; the calibration subset quantifies that bias and the large regime reports its statistics as caveated, never as uniform sampling.
3. **Backbone by pruned calls**, after the sampler. The candidate set starts as the literals true in **every** known sample (the decision model and every known sample j, which are all verified models of F). Process literals in the order 1, −1, 2, −2, …; skip a literal not in the candidate set; for a candidate l, call the oracle on F with the unit clause (¬l) appended after F's clauses. SAT: the verified model (checked against F and the unit) shows that every literal false in it is not backbone; remove all such literals from the candidate set (l among them). UNSAT with a verified proof: l is backbone; remove l from the candidate set and record it. Unknown: the case's backbone is unknown, the procedure stops, and the case is excluded from every backbone statistic. Every call removes at least one candidate, so there are at most n calls, of which exactly |B| answer UNSAT when the procedure completes; the pruning by samples only lowers the count. This is exact relative to the declared oracle, not an estimate; on the calibration subset it must equal the truth-table backbone.

**Calibration calls at 12 variables.** The implementation's regeneration loop solves only formulas above 12 variables and `oracle::label` routes n ≤ 12 to the truth table, so the calibration subset's composed calls need a stated path, which is this: the `solution-geometry` entry of `oracle::EXPERIMENTS` carries, beside `corpus`, a composed-call function that, given a case and the entries kept so far, yields the case's next call (its formula F plus appended units, its declared variable count, and its purpose) in the order of steps 1 to 3 above, or none when the case is done; regeneration runs it to exhaustion for every case of the large regime, after the decision entry the existing loop produces, and for every case of the calibration subset, whose decision call is that function's first call (the existing loop still skips every case with n ≤ 12 and is unchanged); the existing `demo` entry receives a composed-call function that yields nothing, so that the `Experiment` struct's new field is total. In replay the driver looks each composed call up by digest, inserts that digest into the `used` set exactly as `oracle::label` does for a decision lookup, and checks the entry with `oracle::verify` (digest, variable count, conflict limit, model check or LRAT check), never with `oracle::label`; after the corpus the driver calls `oracle::check_used`, so the unused-entry rule covers composed calls, and the truth table stays the reference for every case with n ≤ 12. Calibration entries carry `variables` 12 and `clauses` m plus the appended units; `validate_entry` and the JavaScript answer-file validator impose no lower bound on `variables` and accept them without change. The implementation's restriction of solver calls to formulas above 12 variables is amended accordingly (Amendments to the reference-oracle design, amendment 2).

Per-case call cap: 1 + 3·(⌊log₂(n div 2)⌋ + 1) + n, that is 22 at n = 12, 29 at 16, 33 at 20, and 37 at 24; the corpus cap is 7,260 entries (below), and the expected count is about 2,500 (derivation in the sizing section). Every known sample must satisfy every backbone literal when the backbone is known (a necessary condition that is checked after step 3), and a completed backbone must contain no complementary pair; both are implementation checks. Each known sample is whitened (charged on the geometry meter) and its core size stored; the row stores per sample its assignment as an n-bit integer, its depth, whether it is known, collapsed, or unknown, and the sums and pair counts of pairwise Hamming distances among distinct samples, stratified by the depth pair.

## Fixed corpus

All clauses use the xorshift64 transition above on a 64-bit state. For base seed s, variables n, and clause count m, the initial state (the case's `effective_seed`) is `s XOR (n << 32) XOR (m << 40)`. Draw a ternary clause by repeating: draw `(next() mod n) + 1` as a variable, reject it if already in the clause, and once accepted draw its sign from a fresh draw's low bit, zero meaning positive; stop after three accepted literals. Emit m ternary clauses from one generator; clauses may repeat, and duplicates are written to DIMACS as they are (CaDiCaL accepts them). Densities are α = q/4 and m = (q·n + 2) div 4, the +2 rounding q·n/4 to the nearest integer (halves up); the realized α = m/n is stored as the pair (m, n) and deviates from q/4 only at n = 10 with odd q (q = 15, 17, 19, where m = 38, 43, 48), by exactly 0.05; at n = 8, 12, 16, 20, and 24, q·n/4 = 2q, 3q, 4q, 5q, 6q is an integer for every grid q, so m = q·n/4 and the deviation is 0.

- **Small regime, 720 cases:** n in `8, 10, 12`; q in `8, 12, 14, 15, 16, 17, 18, 19, 20, 22, 24, 32` (α = 2, 3, 3.5, 3.75, 4, 4.25, 4.5, 4.75, 5, 5.5, 6, 8: 0.25 resolution from 3.5 to 5, containing the large regime's six values); replicates r from 0 to 19 with base seed `5011 + 107·r`. The grid runs to α = 8 so that P(SAT) falls below 1/2 at n = 8, where the design-time runs on the round-1 seeds (freshness paragraph) found P(SAT) still about 0.6 at α = 5. The densities q = 10, 13, and 28 are not on the grid, which keeps the artifact within its bound (sizing below); they lie outside the window where the claims and the crossovers are expected to move.
- **Large regime, 180 cases:** n in `16, 20, 24`; q in `8, 12, 15, 17, 20, 24`; replicates r from 0 to 9 with base seed `7027 + 109·r`.
- **Calibration subset, 60 cases:** the small-regime cases with n = 12, q in the large regime's six values, and r from 0 to 9 also run the decision, the sampler, and the backbone as composed calls, with every known oracle label and every completed backbone required to equal the truth table's, every known sample required to be a member of S, and the same statistics computed against the exact model list.

Enumerate the small regime, then the large regime, with n outermost, then q ascending, then r; case ids are `rand3-n{n}-m{m}-s{seed}` with the **base** seed, and each row also stores `effective_seed`. Sum: 823,945 + 52,667 + 351,421 + 324,000 + 60,000 = 1,612,033 bytes compact, about 1.69 MB pretty-printed, 38 % of the 4,194,304-byte bound and under the 1,800,000-byte design target by 187,967 bytes. Ledger ingestion stores the edition's observations as ordered parts of at most 786,432 canonical bytes, each committed as its own ledger operation before the edition (the edition size policy documented in `docs/oh.md` and implemented by `commitInParts` in `scripts/oh-experiment-records.mjs`), so an artifact under the 4 MiB report bound pages part by part within the 8 MiB page bound; the non-observation remainder of the report must stay under 786,432 canonical bytes, and here the remainder (`cells`, `crossovers`, `arm_comparison`, `claims`, `aggregate`, `corpus`, `encoding`, `limitations`) is about 384,000 bytes. A measured replay above 120 s, an answer file above 16 MiB, or an artifact above 4 MiB is a protocol failure resolved only by a new protocol identity with a smaller corpus, never by trimming this one.

## Claims under test and falsification criteria

Every statistic below is either descriptive, labelled so, or tested against the stated null. Expected model-set sizes are stated so that a reader sees what near-threshold "geometry" is at these sizes: E|S| ≈ 4.5 at n = 12 and ≈ 20 at n = 24 at α = 4.25 (2ⁿ·(7/8)^m with m = 51 and 102), a handful of points. Because every raw geometry statistic moves mechanically as |S| shrinks toward one point (a unique model has a full core, every singleton cluster is fully frozen, and the raw distance-1 cluster count is expected to be **non-monotone** in α, rising while |S| fragments and falling as |S| → 1), the pre-registered readings of claims 1 and 2 are **real minus null** on the same formula, claim 3 is a raw SAT-conditional reading whose expected direction is partly mechanical and is labelled so, and the raw curves are descriptive. The claims are uncertain predictions; theorems, accounting identities, and consequences of the fixed corpus and charge table are implementation checks (Acceptance and reporting), never claims.

1. **Backbone excess rises with density (small regime).** Per SAT case with |S| ≥ 2, Δ_B = (|B(S)| − |B(N)|)/n, a signed quantity, with |B(S)| from the reference and |B(N)| from the frozen-variable run on N. When |S| = 1, N is one point, |B(N)| = |B(S)| = n, and Δ_B = 0 identically, a degeneracy of the construction and not a measurement; Δ_B (and Δ_c of claim 2) is therefore **undefined** on a case with |S| = 1: the case's row stores its real and null integers as computed, the case is excluded from every cell mean, crossover, and pair of Δ_B and Δ_c by the definedness rule, and the number of reference-SAT cases with |S| = 1 is reported in every cell and beside every verdict of claims 1 and 2 as the count of pairs dropped by this rule. For each n in 8, 10, 12: Δ_B at q = 17 (α = 4.25) against q = 8 (α = 2) over pairs both reference-SAT with |S| ≥ 2 on both sides, claimed direction higher at q = 17; effect criterion: the mean paired difference under the paired-difference rule (the thousandths mean over all k_def defined pairs, zero differences included) is at least 1/4, with k_def and the sign test's discordant count k both reported. Registered expectation: with E|S| ≈ 2.7 at n = 8 and ≈ 4.5 at n = 12 at q = 17, a sizeable fraction of the SAT cases there has |S| = 1, so k is expected to reach 7 but is not assured to at n = 8, and **not testable** is a registered possible verdict for claims 1 and 2 there, reported with its k and the dropped-pair count.
2. **Excess connectivity falls with density (small regime).** Per SAT case, the connectivity c(X) = 1 − clusters(X)/|X| of the distance-1 graph (0 when every point is isolated, approaching 1 for one connected set) and Δ_c = c(S) − c(N). For each n: Δ_c (signed) at q = 17 against q = 8 over the same pairs as claim 1 (both reference-SAT with |S| ≥ 2 on both sides), claimed direction lower at q = 17; effect criterion: the mean paired difference under the same rule is at most −1/4. On a case with |S| = 1, c(S) = c(N) = 0 and Δ_c would be 0 identically, so the exclusion of claim 1 applies here for the same reason. The raw cluster counts, the multi-cluster indicator, and the distance-2 counterparts are descriptive.
3. **Freezing rises with density (small regime).** Per SAT case the indicator "some model of S is unfrozen (empty whitening core)". This is a raw reading with no null counterpart, since whitening is not defined on N, and its expected direction is partly mechanical: as |S| shrinks toward one model the core fills (a unique model has a full core), so a fall of the indicator with density mixes freezing with the collapse of |S|, which is stated beside the verdict. Two cell fractions are reported: **P_unfrozen**, the fraction of labelled cases of the cell whose formula is satisfiable and has an unfrozen model, over all labelled cases (an unsatisfiable formula is never unfrozen), which targets the same probability as Ardelius and Zdeborová's P_f(α, N), unconditionally over formulas, but is a different estimator: they mark M_f ≤ M_s per instance along a clause-removal path from one formula, whereas this protocol estimates the probability on independent formulas per density; and **P_unfrozen|SAT**, the same indicator's fraction among the cell's reference-SAT cases, which is this protocol's own SAT-conditional estimator and not theirs. The claim pairs the indicator among SAT cases (the conditional quantity): for each n, the indicator at q = 17 against q = 8, claimed direction lower at q = 17; effect criterion: over the k_pairs both-SAT pairs (concordant pairs included), with u_q the number of those pairs whose q-member has an unfrozen model, the exact ratio (u_17, k_pairs) is below (u_8, k_pairs) by at least 1/4, compared by cross-multiplication; k, the discordant count, is reserved for the sign test, and k_pairs is reported beside it. Registered expectation: the sign test counts only discordant indicator pairs, and with P_unfrozen|SAT near 1 at α = 2 and about 0.3 to 0.5 at α = 4.25 the discordant count out of at most 20 pairs is expected near 7 at every n, so **not testable** is a likely verdict at n = 8 and n = 10 and is reported as such together with the effect criterion's value, which is computed over the k_pairs both-SAT pairs whatever the discordant count k is. The size-weighted and unweighted frozen fractions (real and null), the largest-cluster fraction, the restricted fraction over clusters of size at least two, the singleton-cluster fraction, and the fraction of models on which core(σ) ⊂ frozen(K) is strict are descriptive, as Ardelius and Zdeborová's remark that small instances almost always carry a few frozen variables requires.
4. **WalkSAT cost and density.** Primary statistic: flips to solution on reference-SAT cases WalkSAT solved, as flips/n (stored as the integer flips; the cell reports the lower median and the 90th-percentile element ⌈9k/10⌉ of flips/n as `RatioPair`s). For each n in 8, 10, 12, 16, 20, 24: flips at q = 17 against q = 8 over pairs both reference-SAT and both solved, claimed direction more flips at q = 17; effect criterion: over the **paired subset** (the k pairs both reference-SAT and both solved), the lower median of the q = 17 members' flips is at least max(2·m₈, 1), where m₈ is the lower median of the q = 8 members' flips (integer comparison); the floor of 1 keeps the criterion from being vacuous when m₈ = 0, which happens when at least ⌈k/2⌉ of the q = 8 members were satisfied by WalkSAT's initial assignment (a case records 0 flips with probability (7/8)^m if its clauses were independent, about 0.12 at n = 8, q = 8 where m = 16, so a zero median is unlikely but possible); both medians and the number of zero-flip cases on each side are printed in the claims table beside the verdict so that a reader sees when the floor was the binding term, and these two medians are distinct from the cell medians of the curves, which run over every solved SAT case of the cell. Registered expectations, either outcome reported: at n ≤ 12 the success rate on reference-SAT cases is at least 19/20 in every (n, q) cell with at least 10 reference-SAT cases (the budget is expected to saturate the 2ⁿ assignments), and "no success crossover reached" is the expected outcome at every n (the design-time SKC simulation on the round-1 seeds solved every satisfiable case at n = 24 within about 1,100 flips); a cell below 19/20 at n ≤ 12 is reported as an unexpected result, not as a falsification of a claim. In the large regime k ≥ 7 requires at least 7 of the 10 replicates to be reference-SAT and solved at both q = 8 and q = 17; this is expected at n = 16 and uncertain at n = 24, where P(SAT) at α = 4.25 may be near 1/2, so **not testable** is a registered possible verdict there and is reported with its k. Success-within-f-flips curves for f in n, 2n, 4n, …, 1024n are derived from the recorded flip index under a **censoring rule**: a case that returned SAT with flip index F counts as a success at every f ≥ F and a failure at every f < F; a case that returned unknown after F flips counts as a failure at every f ≤ F and is **censored** (excluded from the denominator) at every f > F; the curve at f is the exact ratio (successes at f, cases with a known outcome at f), its population is the reference-SAT cases of one (n, q) cell (an UNSAT case enters no curve, so no curve is depressed by cases no witness finder can solve), one further curve per n pools the reference-SAT cases of all its cells, and the censored count at each f is reported beside every curve. At n = 24, α = 4.25 one flip costs on the order of hundreds of events, the budget buys a few thousand flips, and f = 1024n = 24,576 exceeds that, so the large-f points there are expected to carry censored cases and never understate success by counting an exhausted run as a failure at a flip count it did not reach. The per-flip event cost per cell and the crossover comparison of the first α where success falls below 9/10 with the first α where mean backbone fraction exceeds 1/10 are descriptive.
5. **WalkSAT lands in large clusters with small cores (small regime).** Per reference-SAT case with |S| ≥ 2 and a WalkSAT model W: Q_core(W) and Q_cluster(W) as defined above. Each is a claim on the thousandths mean over all such cases pooled across n, null value exactly 1/2, with the seeded bootstrap interval from pooled streams i = 0 (Q_core) and i = 1 (Q_cluster): **held** when k ≥ 10, the interval's lower element exceeds 1/2 (2·numerator > denominator), and the mean is at least 11/20; **falsified** when k ≥ 10 and either fails; not testable below. Here k counts every pooled case, degenerate cases included, since a degenerate case contributes exactly its null value and can only move the mean toward 1/2; beside each verdict the report prints the number of pooled cases degenerate for that quantile (core size constant over S, or S one distance-1 cluster) and, as a descriptive statistic, the thousandths mean over the non-degenerate cases with its own count. Better, tied, and worse counts of W against the size-weighted mean cluster size Σ|K|²/|S| (larger is better, compared by cross-multiplication) and against the mean core size over S (smaller is better, compared as core(W)·|S| against Σ_U core(U)) are reported as secondary descriptive counts with no P value; they have no 1/2 null.
6. **Sampler bias (calibration subset).** Per calibration case with |S| ≥ 2 and at least two known samples: (a) the mean over known samples of Q_core and of Q_cluster, with the same 1/2 null and bootstrap interval across cases as claim 5 (pooled streams i = 2 and i = 3), labelled **descriptive** with no registered direction, the degenerate-case count and the non-degenerate mean reported as in claim 5; (b) the total-variation distance between the sampled cluster-frequency vector over the s known samples (counts c_K) and the exact size-weighted vector, TV = Σ_K |c_K·|S| − |K|·s| over 2·s·|S|, exact, with no interval; (c) the same (a) and (b) for a seeded null of s uniform draws with replacement from S (`next() mod |S|` on the calibration-null stream, indexing the sorted list), the null quantile means with pooled streams i = 4 and i = 5. The registered usability criterion is that the difference of the two thousandths means, mean TV(real) − mean TV(null) over the k such cases (a `SignedRatioPair`, compared to 1/10 by cross-multiplication), is at most 1/10; the verdict is `met` or `not met`, `not evaluable` when k = 0, and above the threshold every large-regime sample statistic is reported flagged "sampler bias exceeds criterion"; k is printed beside the verdict. Sample statistics are stratified by depth r, collapsed samples are counted per case, and the artifact states that bias measured at n = 12, where the solver may decide by preprocessing alone, need not transfer to n = 24.
7. **Large regime (descriptive with registered thresholds).** With 10 replicates per cell and SAT-conditioned pairing, k ≥ 7 pairs is not expected, so the large regime carries no sign test; each statement is reported as met or not met against its threshold, with the per-cell seeded bootstrap intervals (per-cell streams i = 0 and i = 1) reported beside the point means, and labelled descriptive. The two claim-7 quantities are **exempt from the 10-SAT rule** of the curves section: each is computed in the claims table directly from the rows over the k defined cases of the cell (oracle-SAT with a known backbone for |B|/n; oracle-SAT with at least two distinct known samples for the sample distance), k is reported for both cells of every comparison, and a comparison is **evaluable** only when k ≥ 5 on both sides, otherwise "not evaluable (k < 5)" is the reported outcome. For each n in 16, 20, 24: the cell mean of |B|/n (the exact ratio (Σ|B|, k·n)) at q = 17 exceeds that at q = 8 by at least 1/4; and the cell mean of the per-case mean pairwise distance over n among distinct known samples (depth-stratified table alongside) at q = 17 is below that at q = 8 by at least 1/10. The second threshold has no null counterpart and is expected partly mechanically: E|S| falls from tens of thousands at α = 2 to about 20 at n = 24, α = 4.25, and distinct samples drawn from a smaller set lie closer, so a met threshold is a bounded observation about sampled distances at these sizes and not evidence of clustering beyond the collapse of |S|; this is printed beside the outcome. Registered expectation: at q = 8 every case is expected SAT with a known backbone; at q = 17 the number of SAT cases among 10 is binomial, so k ≥ 5 is reached with probability about 5/8 if P(SAT) = 1/2 and about 19/20 if P(SAT) = 7/10 (finite-size P(SAT) at n = 24, α = 4.25 is expected between those; the solver probe of the freshness paragraph saw 3 of 3 satisfiable at n = 24, q = 17 on other seeds), and "not evaluable" at n = 24 is a registered possible outcome, reported like any other. The curves-section cell means of the same quantities remain under the 10-SAT rule and may be `null` where the claims table shows a value with its k. The large regime has no null point set because |S| is unknown there, which is stated with the numbers.

No claim concerns asymptotics; every claim is a statement about these 900 formulas. Crossover densities, drift with n, and successive ratios are descriptive numbers under the finite-range caveat and carry no growth label.

## Reference, budgets, and accounting

For n ≤ 12 the reference is the direct truth-table evaluator admitting width three (`implication::reference_wide` and a sibling enumerator in the same style that also returns the sorted model list, asserted to agree with it on count and backbone), enumerating all 2ⁿ assignments after both arms return and recording the model count, label, backbone, and the sorted model list on which clustering runs; its work is reported outside the arms. For n ≥ 16 the reference is the declared oracle, through `oracle::label`; the truth table remains the reference for every case at 12 variables and below, including the calibration subset, where composed-call answers are compared to it and never replace it.

**Oracle.** CaDiCaL 3.0.1 at `/opt/homebrew/bin/cadical`, digest `601c9fa8ba5d09fd81bb00c89b3e54832f138bccc3422bd8652e8cda4d74d1fa` computed by the in-tree SHA-256 over the resolved link target (`fs::read` follows the Homebrew symlink into the Cellar), checked by `identity()` before any live call; a digest or version mismatch refuses regeneration before any solve. Invocation, output parsing, exit-code and `s`-line agreement, wrapped `v` lines, and edge inputs are the design's; conflict counts are never read. Every call uses `-c 10000`, never a time limit, with `--lrat --binary=false`. The model checker charges, on its own fresh meter whose work the driver adds to the checker totals: one formula check, one container write for the assignment array, one scalar write per variable, one clause read per clause, and one scalar read per literal examined until the clause is satisfied. The LRAT checker (`check_lrat`, the std-only RUP-with-hints checker with deletions honoured and the final empty clause required) charges formula checks, clause reads, literal reads, and literal writes, exactly the ticks of `lrat::propagate`, and no other category. No second solver is used; the checked proof is the UNSAT evidence, and the checked model the SAT evidence. Unknown (conflict limit or proof over cap) keeps the case, labels the quantity unknown with its reason, excludes it from comparisons, and does not invalidate the run.

**Oracle-answer file and replay.** `artifacts/solution-geometry-oracle.json` (the default path of both commands, `answers_path("solution-geometry")`) is written only by `oracle-answers solution-geometry` on a host whose binary matches the pins, in the implementation's fixed serialization (entries sorted by digest, no case ids, `schema_version` 1, `experiment` `solution-geometry`, the identity block, the proof cap). Regeneration never runs an arm. The `solution-geometry` command is replay mode: it regenerates the corpus, runs both arms on every case, then per case performs the truth-table or oracle reference and the composed calls above, looking each call up by digest, re-verifying every model and every proof, and refusing on a missing, duplicate, unused, or mismatching entry or on an answer file whose `experiment` field is not `solution-geometry`; it invokes no solver and reads no solver path. `bun run check` runs replay mode on every machine and must reproduce `artifacts/solution-geometry.json` byte for byte; where the pinned binary is present, the gate also regenerates the answer file and requires byte identity with the committed one, and `PEQNP_REQUIRE_ORACLE=1` turns a skipped regeneration into a failure (the final gate for any change to the answer file, run on the host that produced it). A regeneration difference is a finding to report, never accepted silently. The artifact's `oracle_answers.path` is the constant `answers_path("solution-geometry")`, that is `artifacts/solution-geometry-oracle.json`, whatever path `--oracle-answers` names (the gate passes an absolute host path, which must not reach the artifact), and `oracle_answers.sha256` is the SHA-256 of the answer-file bytes read. Wall-clock seconds per solver call go to the uncommitted sidecar written by regeneration only, which is never byte-compared, never recorded in the ledger, and never cited in a claim; replay's wall time is the gate's printed figure and is recorded nowhere in the repository.

**SHA-256** is `src/sha256.rs`, the std-only FIPS 180-4 implementation pinned to the NIST vectors in the design (empty, `abc`, the 448-bit message, one million `a`, and the streaming split); no crate.

Reuse the checked event counters and unit increments of the earlier experiments; the geometry procedures charge exactly the reads, writes, pair checks, and search nodes stated above. Timeout, budget exhaustion, and the conflict limit mean unknown, never a decision and never a refutation. Compare WalkSAT and the baseline only on cases both complete with a known label; do not treat an unfinished arm's smaller work count as a speedup. The baseline copies the formula at every node (`transfer::restrict`), so a node at n = 24 costs several hundred events and the budget admits a few thousand nodes; the two design-time simulations disagreed on whether that decides most n = 24 cases, so the expectation is registered as uncertain, the per-cell both-complete count is reported, and the arm comparison at n = 24 is a selected subsample whenever unknowns arise. The baseline DPLL has no polynomial bound; WalkSAT has no completeness; enumeration is exponential by construction; the oracle's internal work is outside the cost model and its bound is unknown. Measured totals prove none of these statements, and no finite experiment proves an asymptotic bound.

## Curves and interpretation fixed in advance

Per (n, α) cell, with per-case integer rows in the artifact and thousandths mean, lower median, minimum, and maximum in the summary: the number of cases and the number labelled unknown and why; P(SAT) over labelled cases; median model count and mean bit length over SAT cases (small regime); |B|/n over SAT cases with known backbone (both regimes), the null backbone fraction and Δ_B over cases with |S| ≥ 2 (small regime), the count of reference-SAT cases with |S| = 1, and the count of unknown backbones; distance-1 and distance-2 cluster counts, connectivity, the multi-cluster fraction, and the null counterparts and Δ_c (small regime); the Ardelius–Zdeborová complexity proxy, reported as the integer cluster count of the median-|S| case in the cell together with the pair (bit length of that count − 1, n), never a logarithm; P_unfrozen (unconditional, the Ardelius–Zdeborová probability estimated on independent formulas) and P_unfrozen|SAT (this protocol's SAT-conditional estimator), each labelled; size-weighted, unweighted, largest-cluster, and restricted frozen fractions, the singleton-cluster fraction, and the null counterparts (small regime); minimum and mean inter-cluster distance and mean pairwise distance, real and null (small regime); core fraction averaged over all models and the fraction of models with strict inclusion core(σ) ⊂ frozen(K) (small regime), and core fraction over known samples (both regimes); known, distinct, collapsed, and unknown sample counts, depths, and depth-stratified sample distances (large regime and calibration); baseline events, search nodes, and unknown count with the right-censored median; WalkSAT success rate on reference-SAT cases, flips/n median and 90th percentile, events per flip, success-within-f-flips at the listed f over the cell's reference-SAT cases with the censored count at each f (and the pooled curve per n), and budget exhaustion on UNSAT cases; claims 5 and 6 quantile means with intervals, degenerate counts, and the secondary counts; oracle call counts, verified-proof lemma counts, and unknown counts per purpose (decision, sample, backbone); per-cell totals of the geometry, reference, and checker meters by category (the checker totals include every WalkSAT model check and every composed-call model and proof check of the cell). Means over SAT cases are `null` in any cell with fewer than 10 reference-SAT cases (high-α SAT-conditioned cells are a survivorship sample), except the two claim-7 quantities, which the claims table reports under claim 7's own k ≥ 5 rule; the SAT-case count and every mean's k appear in every cell. The SAT/UNSAT split of every curve uses the reference label assigned after both arms returned; unknown-label cases appear in neither split.

Crossovers per n, descriptive, indexed as in the bootstrap enumeration: (0) the first grid α where P(SAT) falls below 1/2, (1) where mean Δ_B exceeds 1/10 and (2) 1/4, (3) where the unconditional P_unfrozen falls below 1/2 (Ardelius and Zdeborová's crossing point) and (4) where P_unfrozen|SAT falls below 1/2, (5) where the multi-cluster fraction exceeds 1/2, and (6) where WalkSAT success falls below 9/10 and (7) 1/2, each `null` ("not reached") when never reached on the grid, which is the expected outcome for the success crossovers; a `null` cell mean satisfies no crossover condition. Crossovers 1, 2, 4, 5, 6, and 7 are SAT-conditioned means under the 10-SAT rule (the WalkSAT success rate is a fraction over the cell's reference-SAT cases), so with 20 replicates they can be reached only at densities where at least 10 cases are satisfiable, that is at or before crossover 0; "not reached" for those six is therefore partly mechanical and is reported with the last grid α at which the mean was defined. Each crossover carries the seeded bootstrap interval of its crossover stream (resampling replicate indices, the one drawn index multiset applied to every cell of that n, B = 1,000, "not reached" sorting as +∞ so an interval bound may be `null`); drift from n = 8 to 24 is stated in words only where the intervals of the two named n do not overlap, and the change of reference, replicate count, and grid at n = 16 is named beside it. Successive ratios of median model count between consecutive n at fixed q are reported as `RatioPair`s with the caveat that six sizes on a finite range distinguish no growth class; no "polynomial-like" or "exponential-like" label is assigned to any series. Report the small regime, then the calibration subset, then the large regime, then the arm comparison, then the claims table, then any aggregate.

A backbone or connectivity excess that rises sharply with density at these sizes would mean that the finite-size shadow of the predicted transitions is visible, beyond the collapse of a random point set of the same size, to exhaustive and oracle tooling at 8 to 24 variables, and it would locate the density window where forced literals are numerous, which is where a future interface experiment should draw its formulas. It would not establish a phase transition, an asymptotic geometry, an algorithmic barrier, or any statement about worst-case complexity or P versus NP: the physics values are cavity-method predictions, rigorous clustering results exist only for larger k, and 24 variables cannot separate a crossover from a transition. A backbone computed by an oracle is instance-specific assistance in the framework's taxonomy; knowledge of α or of the typical geometry at α is distributional knowledge that yields at most a heuristic, not advice in the P/poly sense and not an algorithm. WalkSAT's flip curve is a measurement of one local-move solver with one noise value; if its cost rises where frozen variables appear, that is a bounded observation consistent with the local-move intuition, and if it does not, the intuition is unsupported on this corpus. Survey propagation is named as future work and is not implemented.

## Artifact layout

The frozen artifact at the freeze commit is the schema authority; this section fixes the order so that two implementations agree byte for byte. Top-level keys in order: `schema_version` (1), `experiment`, `status` (`bounded-tested`), `proof_status` (`no-formal-proof`), `protocol_sha256`, `arm_budget`, `counter_model`, `reference_model`, `oracle_limits` (`{"conflicts":10000}`), `proof_text_cap_bytes`, `oracle_answers` (`{"path","sha256"}`, the constant answer path and the SHA-256 of the answer-file bytes), `limitations`, `corpus` (generator, seed formula, seeds, grids, case count, overlap count, earlier corpora checked), `encoding` (assignments as n-bit integers, backbones as literal lists, work vectors and their field order, the geometry digest text, `RatioPair` and `SignedRatioPair`, thousandths mean, medians, bootstrap stream enumeration, call records and `calls_sha256`, the positional orders below), `observations` (one row per case in enumeration order), `cells` (one object per (n, q) in enumeration order, 54 in all), `crossovers`, `arm_comparison`, `claims` (one object per claim with its k, k_def or k_pairs where defined, s, P, effect value, threshold, interval, degenerate count where defined, and verdict), `aggregate` (the corpus totals of oracle calls, unknowns, and verified-proof lemmas, and the answer-file SHA-256, which the evidence record described in `docs/oh.md` carries as `oracleCalls`, `oracleUnknown`, `proofLemmasTotal`, and `answersSha256`).

Per-case row keys in order: `id`, `variables`, `clauses`, `base_seed`, `effective_seed`, `q`, `dimacs_sha256` (of `write_dimacs(F, n)`; no `input`), `reference` (small regime: `{"kind":"truth-table","model_count","sat","backbone","work"}` with `work` a work vector, serialized by the driver itself rather than through `Label::json()`; large regime: the design's oracle object in full, keyed `work` objects included, exactly as `Label::json()` emits it), `baseline` (`outcome`, `search_nodes`, `work` vector), `walksat` (`outcome`, `model` as an n-bit integer or `null`, `flips`, `work` vector, `model_check_valid`; the model check's work appears in the cell's checker totals, not in the row), `geometry`, `calls`, `calls_sha256`, `call_work`. A work vector is the positional array of the ten `Work` integers in `Work::json` order (sizing section). `geometry` on a small-regime UNSAT case is `{"models":0}`; on a small-regime SAT case its keys in order are `models` (|S|), `clusters` `{count, sizes, frozen, largest, secondary_count}` with `sizes` and `frozen` (per-cluster frozen counts) in cluster order, `frozen_sums` (the positional array `[Σ_K |K|·frozen(K), Σ_K frozen(K), frozen(largest), |B|, singletons, Σ_{|K|≥2} |K|·frozen(K), Σ_{|K|≥2} |K|]`), `distances` (`[minimum over cluster pairs, sum of minima, cluster pairs, pairwise distance sum, point pairs]`), `whitening` `{core_histogram (n+1 counts by core size), unfrozen_models, strict_inclusions}`, `null` (`clusters`, `frozen_sums`, and `distances` in the same shapes for N, plus `backbone_count`, that is |B(N)|), `quantiles` (`[Q_core numerator, Q_cluster numerator]` over 2·|S| for the WalkSAT model, or `null` without one), and `digest` (the geometry digest of the sizing section); a case with |S| = 1 stores these fields as computed and is excluded from Δ_B and Δ_c by the rule of claim 1. On calibration rows and large-regime SAT rows `geometry` also carries `samples` (per sample in index order the positional array `[assignment or null, depth or null, state, core size or null]` with state 0 known, 1 collapsed, 2 unknown) and `sample_distances` (per depth pair among distinct known samples `[depth_a, depth_b, distance sum, pairs]`); on a large-regime UNSAT or unknown row `geometry` is `null`. `calls` is the list of compact call records in call order, beginning with the decision record in both regimes (on a large-regime row its `label`, `model`, and `lemmas` repeat the `reference` object's and its check work is inside `reference`, not `call_work`), each the positional array `[purpose, index, depth, units, label, model, lemmas, reason]` with `purpose` one of `decision`, `sample`, `backbone`, `index` the sample number j or the backbone literal l (0 for the decision), `depth` r for sampler calls and `null` otherwise, `units` the appended unit literals in order (empty for the decision), `label` one of `sat`, `unsat`, `unknown`, `model` the verified model as an n-bit integer or `null`, `lemmas` the verified proof's lemma count or `null`, and `reason` the unknown reason or `null`; `calls_sha256` is the digest chain of the sizing section and chains the decision digest first; `call_work` is `{"decision":[model_check, proof_check],"sample":[…],"backbone":[…]}` with work vectors summed per purpose and kind, the `decision` key present only on calibration rows (in the large regime the decision call's checks are inside `reference`). On small-regime rows outside the calibration subset `calls`, `calls_sha256`, and `call_work` are `null`. The compact call record is this protocol's deliberate departure from the design's per-call oracle object, made for the size arithmetic above and recorded as amendment 1 below: replay still re-verifies every composed call's model and proof; only the per-call `work` objects, the per-call digests, and the repeated identity block are not stored per call. Sample and WalkSAT models are n-bit integers; no proof text is in the artifact.

Registration follows the gate-and-CLI section below. The ledger validator, for every row, regenerates F from `effective_seed`, `variables`, and `clauses` with the frozen generator, requires `write_dimacs(F, n)` to hash to `dimacs_sha256`, and works on the reconstructed row; it applies the design's `oracleReference` to every large-regime row's `reference` unchanged; it checks a small-regime `reference` by the design's truth-table rules (`variables ≤ 12`, `assignments = 2ⁿ`, model count and sat flag, backbone shape) with the work vector expanded to the keyed shape before the shared `work()` check; for every compact call record of a large-regime or calibration row it regenerates the call's DIMACS text from the reconstructed F and the record's `units`, requires an entry with that text's digest and the record's `label` in the answer file, requires the chain of those digests to hash to `calls_sha256`, requires a `sat` record's `model` to equal the entry's model as an n-bit integer and to satisfy F and the units (recomputed), requires an `unsat` record's `lemmas` to equal the number of non-deletion lines of the entry's proof text and its `model` to be `null`, requires `reason` to be `null` unless the label is `unknown` and equal to the entry's reason otherwise, and requires every `call_work` vector to expand to the `work()` shape; it checks the geometry object's integer consistency and the form of `digest` as stated in the sizing section; and it checks every `RatioPair` and every `SignedRatioPair` by `BigInt` (the magnitude rule on |a|, `negative` false whenever the numerator is 0, and the leading `-` of `thousandths` present exactly when `negative` is true and the numerator is positive).

## Amendments to the reference-oracle design

The reference-oracle implementation is merged (PR #7) and documented in `docs/oh.md` and the README; this protocol departs from its artifact conventions on the three points below. Each is a reference-oracle change needing independent review per `AGENTS.md`, is reviewed with the freeze change, and changes nothing in the answer-file format, the solver pin, the checkers, `oracle::label`, `oracle::verify`, or the shared `oracleReference` validator, which every large-regime `reference` object still passes unchanged.

1. **Compact call records.** The merged implementation's convention for an oracle answer is one `OracleVerdict` per call, the keyed object `OracleVerdict::json` emits (which `Label::json()` places in a row's `reference` and `oracleReference` in `scripts/oh-report-checks.mjs` checks once per row) and `Summary::include_call` counts; no repository text places a composed call's object under the case or states its appended units. Amendment: a protocol may instead store each composed call as the compact call record of the artifact layout (`[purpose, index, depth, units, label, model, lemmas, reason]`) with one `calls_sha256` per row over the per-call DIMACS digests and the checker work of the composed calls summed per purpose and kind in a sibling `call_work` object, provided replay still re-verifies every composed call's model and proof and the ledger validator applies the rule this amendment adds under the name `compactCall`: regenerate the call's DIMACS text from the case's formula and the record's `units`, require an entry with that digest and that `label` in the committed answer file, require the digest chain to hash to `calls_sha256`, require a `sat` record's `model` to equal the entry's model as an n-bit integer and to satisfy the formula and the units, require an `unsat` record's `lemmas` to equal the entry's non-deletion line count and its `model` to be `null`, require `reason` to be `null` unless the label is `unknown`, and require every `call_work` vector to expand to the `work()` shape. This protocol uses that option for the size arithmetic above.

2. **Composed calls at 12 variables.** The merged implementation issues solver calls only above 12 variables: `oracle::regenerate` skips every case with `variables <= TRUTH_TABLE_MAX_VARIABLES` (12), `oracle::label` routes those cases to the truth table, and the `Experiment` struct carries only `name`, `limits`, and `corpus`, so no composed call can be produced today and no committed answer file holds an entry at 12 variables or fewer. Amendment: a protocol may name composed calls on cases at 12 variables or fewer for calibration against the truth table, produced in regeneration by the experiment's composed-call function (the `Experiment` struct gains that function beside `corpus`, with a no-op function on the existing `demo` entry) and checked in replay by `oracle::verify` with the digest inserted into the `used` set; the truth table remains the reference for every such case, `oracle::label` is unchanged, and an entry's `variables` may be 12 or fewer, which `validate_entry` and the JavaScript validator already accept. The path this protocol takes through the amendment is stated in the oracle-procedures section.

3. **Row compaction.** The six committed artifacts and their validators store the ordered clause list as `input` on every row (`oracleReference` reads `row.input`), keyed `work` objects everywhere (the shared `work()` check of `scripts/oh-report-checks.mjs`), and the truth-table reference as `Label::json()` emits it. Amendment: a protocol whose corpus is a deterministic function of per-row seeds may omit `input` in favour of `dimacs_sha256` and a validator that regenerates the formula, may store every `work` object outside the oracle `reference` object as a work vector with the field order fixed in `encoding`, and may serialize the truth-table reference itself with a work vector, provided the validator reconstructs the row before applying `oracleReference` (large-regime rows) or the truth-table rules (small-regime rows), and provided the Rust replay recomputes every omitted value on every gate run. This protocol uses all three options for the size arithmetic above.

## Acceptance and reporting

**Implementation checks.** Each of the following follows from a theorem, an accounting identity, or the fixed corpus and charge table; a violation is an implementation defect, never a result, and is resolved transparently before publication with the frozen design preserved: core(σ) ⊆ frozen(K) for every model σ of every small-regime SAT case and B ⊆ frozen(K) for every real cluster K (the proved containment); every union-find run's cluster sizes sum to the point count and the singleton count equals the number of size-1 clusters; every inter-cluster minimum is at least 2 in the distance-1 graph and at least 3 in the distance-2 graph; the null set has exactly |S| distinct members; the sibling enumerator agrees with `reference_wide` on model count and backbone; `definition_cases = 0`; Δ_B = Δ_c = 0 on every case with |S| = 1; the mid-rank quantile of every model equals the identity value 1/2 on every degenerate case; the per-case call count is within the cap 1 + 3·(⌊log₂(n div 2)⌋ + 1) + n, exactly |B| backbone calls answer UNSAT when the backbone completes, a completed backbone contains no complementary pair, and every known sample satisfies it; on the calibration subset every known oracle label and every completed backbone equals the truth table's and every known sample lies in S; the realized α deviates from q/4 only at n = 10 with odd q, by 0.05; the answer file contains exactly the calls the corpus makes; the geometry digest, `dimacs_sha256`, and `calls_sha256` of every row are reproduced by the validator's regeneration where it regenerates and by replay's byte identity otherwise.

Every completed baseline decision and every WalkSAT SAT answer must agree with the reference label when it is known; every WalkSAT model and every oracle model must pass `check_model`; every accepted UNSAT answer must carry an LRAT proof `check_lrat` verifies; the binary's digest must match before any live call; replay must reproduce the artifact byte for byte and, where the binary is present, regeneration must reproduce the answer file byte for byte; the gate's printed replay time must be under 120 seconds, the answer file under 16 MiB, and the artifact under 4 MiB. A violation invalidates the run; repair implementation bugs transparently before publication, preserving the frozen design. An oracle unknown is not a violation. Algorithm, parameter, or corpus changes prompted by observed performance require a new protocol identity. Keep every case, model count, backbone, cluster size list, frozen count, distance sum, core histogram, sample, null value, oracle-answer entry, arm outcome, unknown reason, digest, and counter. No required result is a positive delta or a visible transition; a negative result, including every falsified, not-testable, or not-evaluable claim and every "not reached" crossover, is reported with the same completeness as a positive one.
